# IELTS Writing Lab｜观点表达记忆室（v11：固定组完成机制）

纯静态网站，可部署到 GitHub Pages。保留原有界面、12 个主题、600 条表达、表达总库、搜索、语音朗读、英美拼写兼容、进度备份和导入。

## v11 的核心改变：固定组、全部通过才能继续

- **新表达**：选择每组 5、10、15、20 或 30 条后，系统锁定本组的确切名单。每条先根据中文猜想，显示英文与例句，隐藏答案后进行拼写。**本组每条都正确拼写至少一次，才会出现“这一组完成了”**，然后才能开始下一组。
- **间隔复习**：同样固定每组的表达名单，每条独立拼写。**所有条目各正确一次才算完成这一组**。复习通过的表达标记为已掌握；未通过的表达不会被算作已完成，也不会流入下一组。
- **答错后的处理**：当次显示正确答案和例句供对照。点击“继续本组”先练剩余未通过的表达；这一轮走完后，会在**同一固定组**内再次出现错误项，直到它拼写正确。若本组只剩一条未通过，则会继续练这一条。错误也会记入学习记录，但不能推进本组的完成数。
- **固定范围与中断续练**：组别创建后不受后续更改主题筛选、组数设置或切换模式影响；修改设置仅对**下一组**生效。当前组名单、每条通过状态会保存在浏览器本地；刷新、暂时离开或返回该模式后，会继续未完成组。学习和复习分别保存各自未完成的组；单独在表达总库点“练这一条”不会覆盖它们。
- **不能跳过**：为保证真正完成，训练中的“上一条／下一条”跳转按钮不可用；应先核对拼写，然后点击“继续本组”。

## 更简洁的卡片提示

每条卡片原来的长句提示改为：

| 模式 | 核对前／核对错误 | 核对正确 |
| --- | --- | --- |
| 新表达 | `学习0/1` | `学习1/1` |
| 间隔复习 | `复习0/1` | `复习1/1` |

成功判定会在点击“核对”时**立即计入并保存**，不需要等到点击下一条。卡片上方同步显示“本组已通过 X/Y”。核对后保留你输入的答案，标准表达及例句显示在拼写框下方，方便逐字比较。

已删除拼写框下方的常驻文字“英式／美式规范拼写均认可……”。**判定规则并未改变**：例如 `globalisation/globalization`、`centre/center`、`organisation/organization` 等经核实的英美拼写变体均认可；真正的字母、词形、词序、搭配错误仍判错。如果使用规范的地区变体，核对反馈仍可能说明被认可的拼写差异。

## 间隔复习和学习记录

- 新表达首次正确拼写后，学习等级升为 1，约 1 天后进入复习；复习正确一次即判定掌握，安排下次间隔复习。
- 当前组内拼写失败会暂存一个约 10 分钟后的到期时间，但**组内重练不会等待到期，也不允许把错误条目留到下一组**；最终通过后将正常设置下一次复习时间。
- 当日已完成条目的新增计数只在正确拼写时记录；老版本已保存的计数不会被强制重置。
- 本地进度使用与 v7—v10 相同的 `ieltsWritingLab.v3.spelling-progress`，已有学习和掌握记录均保留；新版本增设 `activeBatches` 用于保存未完成组，备份/导入可连同未完成组迁移。
- 练习组数仍可分别设置“新表达每组”和“复习每组”，默认都是 10 条。

## 部署更新

1. 先在旧网站点击“备份进度”，保存 JSON 备份。
2. 解压 ZIP，上传并覆盖 GitHub 仓库中的 `index.html`、`style.css`、`app.js`、`words.json`、`README.md`。
3. 等待 GitHub Pages 部署完成，刷新页面；如出现旧版本缓存，请强制刷新。
4. 如需本地测试，使用静态 HTTP 服务器（例如 `python -m http.server 8000`），而不是直接双击 HTML 文件。

网站只在当前浏览器的本地存储中保存学习进度，换浏览器或设备可用“备份进度”和“导入进度”恢复。词库保持原样，全部 600 条及其例句没有改动。
